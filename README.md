# 蓝牙锁 连接密码修改工具（Android）

给客户收货后把锁的**蓝牙连接密码**从出厂 `000000` 改成自己密码用的独立小工具。
改完之后，只有知道新密码的 APP 能连接并操作这把锁。

> 协议依据：《智能锁4G+蓝牙通讯协议 v2.0》（`abd-ble-tool` 仓库）。
> 2026-09-30 重写：旧版按一个不存在的固件写了一套明文协议，对真锁一条都发不进去，已整体替换。

## 适用

| 项目 | 要求 |
|---|---|
| 锁固件 | 4G-BLE-093 / ABD-BLE-806，**v1.7 及以上**（0x21 改密从 v1.7 起支持） |
| 手机 | Android 5.0+，支持 BLE |
| 权限 | 蓝牙、位置 |

## 使用

1. 按锁的按键唤醒（红灯慢闪 = 在广播）
2. 打开工具 → **扫描** → 列表里点选 `LOCK_xxxxxxxxxxxx`
3. **连接**（状态栏显示"已连接"）
4. 旧密码栏默认 `000000`，可先点 **验证密码** 确认
5. 填新密码（6 位数字）→ **修改密码**
6. 看到"密码已改为 ……"即成功；建议断开重连、用新密码点一次「验证密码」

密码错锁回 `01` 不断开，可以改了再试；锁鉴权后 60 秒无操作会自己断开休眠，重新按键再连即可。

## 它做了什么（对应协议）

```
连接 → 开通知
0x10 对时        用 key1 加密        key1 = MAC + 11 22 … AA
   ← AA id 10    锁按这次的时间生成 key2
0x20 旧密码      用 key2 加密        key2 = key1[10..15] ← 年月日时分秒
   ← AA id 20 00
0x21 新密码      用 key2 加密
   ← AA id 21 00 写入 Flash，立即生效
```

每帧 AES-128-ECB，16 字节容器 `FB | len | 帧 | FC…`。
密码每位一个字节 0–9（不是 ASCII），校验和 = 指令ID 到参数末尾累加低 8 位。

## 代码

| 文件 | 作用 |
|---|---|
| `BleLockSdk.java` | 协议：密钥派生、组帧、AES、解析 |
| `BluetoothConnectionManager.java` | 扫描、连接、开通知、原样收发 16 字节 |
| `MainActivity.java` | 流程状态机（对时 → 验密 → 改密）与界面 |

## 编译

GitHub Actions 自动构建（push 后到 Actions 下载 `app-debug` 里的 APK），或本地 `./gradlew assembleDebug`。

## 排错

| 现象 | 原因 |
|---|---|
| 扫不到 | 锁没唤醒；或没给位置权限 |
| 连接失败 "未找到锁服务" | 不是我们的锁 / 固件不对 |
| 对时无回复 | 通知没开成功、锁已休眠；日志里看 key1 是否等于 MAC + 11 22…AA |
| 验证密码无回复 | 0x10 后超过 10 秒才发 0x20，断开重连再试 |
| 修改密码无回复 | 固件低于 v1.7 |
| 密码错误 | 旧密码不对；出厂是 000000，客户可能已经改过 |

日志按钮可以复制全部收发明文，反馈问题时带上。
